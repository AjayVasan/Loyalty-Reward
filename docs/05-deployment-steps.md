# Deployment Steps — BAS → Build Code → Cloud Foundry

## 1. Bring this project into your BAS dev space

You already created a `loyalty-rewards` project in BAS via "Create a new project with
template" → CAP → Node.js → PostgreSQL (local) → Cloud Foundry: MTA Deployment → XSUAA +
Approuter + HTML5 App Repository → Extended Sample with UI. This project mirrors those same
choices so the two can be merged:

1. Push this repository to a git remote you control (GitHub/GitLab).
2. In your BAS dev space terminal, inside the existing `loyalty-rewards` project folder:
   `git remote add plan <your-remote-url> && git fetch plan`
3. Replace the generated sample content with this project's `db/`, `srv/`, `app/`,
   `xs-security.json`, `mta.yaml`, and `package.json` — either
   `git checkout plan/master -- db srv app xs-security.json mta.yaml package.json`
   or copy the files manually via the BAS file explorer.
4. `npm install` again inside BAS to pick up the added dependencies
   (`@cap-js/change-tracking`, `@sap/xssec`, `cds-plugin-ui5`, etc).

## 2. Local verification in BAS

```bash
npm test
```
Confirm all 14 automated tests pass (this uses an in-memory SQLite DB, no external service
needed).

```bash
cds watch
```
Confirm the service starts against your local PostgreSQL, the seeded RewardPolicy/TierThreshold/
Customer rows are visible via `GET /odata/v4/loyalty/Customers`, and each of the four Fiori apps
opens and renders (`/customersapp/index.html`, `/transactionsapp/index.html`,
`/rewardpolicyapp/index.html`, `/tierthresholdapp/index.html`).

## 3. Bind to your real HANA Cloud instance for a hybrid test (recommended)

```bash
cds bind -2 <your-hana-service-instance-name>
cds watch --profile hybrid
```
This runs the app locally against your actual SAP BTP trial HANA Cloud database instance before
a full cloud deployment — catches HANA-specific issues early.

## 4. Build and deploy the MTA to Cloud Foundry

```bash
cf login --sso
cf target                      # verify the correct org/space
mbt build -t gen --mtar mta.tar
cf deploy gen/mta.tar -f
```
The final log line prints the Approuter URL — that's your application's entry point. The MTA
(`mta.yaml`) was generated by `cds add mta` and covers all four Fiori apps, the CAP service, the
HANA DB deployer, and the approuter as a single deployable unit — one `cf deploy`, no
microservices.

## 5. Assign role-collections to your user

In the BTP Cockpit → Security → Role Collections, find `Loyalty-Customer (<space>)`,
`Loyalty-Staff (<space>)`, `Loyalty-Admin (<space>)` (created by `mta.yaml`'s xsuaa resource) and
assign the ones you need to your BTP user (or test users) so you can log in as each role and
demonstrate the four Fiori apps end-to-end.

## 6. Capture evidence

Screenshot: the running Approuter URL, each of the four Fiori apps with real data, and a
`GET .../Customers/{id}/changes` response showing an audit trail entry — this is the "executed to
display the output" evidence the source assessment's Important Note requires.
